# M10-S1：现有 Agent 控制平面之上的 MCP 薄适配

本切片没有用 MCP 重写 ArtFlow，也没有把 Unreal、ComfyUI 或本机文件系统开放给模型。它只把
已经存在且经过验证的 Scene Digital Twin、M9 生命周期与独立验证结果投影为固定资源，并把现有
DAG 编译、失败域检查和发布复核投影为内容寻址的只读工具。

## 协议与实现选择

实现采用官方 Python SDK `mcp 2.1.1`，依赖范围锁在 `>=2.1,<2.2`。跨进程运行通过 stdio 协商到
协议版本 `2026-07-28`。当前规范取消了旧式全局握手状态，强调按请求能力发现和显式应用状态；这与
ArtFlow“协议层不拥有第二状态机”的边界一致。参考：

- [MCP 2026-07-28 规范更新](https://blog.modelcontextprotocol.io/posts/2026-07-28/)；
- [官方 Python SDK 2.1.1](https://github.com/modelcontextprotocol/python-sdk/releases/tag/v2.1.1)；
- [官方 Python SDK 文档](https://py.sdk.modelcontextprotocol.io/)。

## 对外暴露面

固定 Resources：

| URI | 来源 |
| --- | --- |
| `artflow://scene/current/twin` | M7 真实 UE Scene Digital Twin ZIP 成员 |
| `artflow://runs/m9/lifecycle` | M9 SQLite append-only 九事件账本 |
| `artflow://runs/m9/verification` | M9 独立验证报告 |

只读 Tools：

| Tool | 允许输入 | 复用的内部能力 |
| --- | --- | --- |
| `scene.twin.summarize` | Twin SHA-256 | `SceneDigitalTwin` 合同校验与事实摘要 |
| `scene.delta.compile_registered` | 已注册计划 SHA-256 | 原有 `compile_multi_domain_dry_run` DAG 编译与能力路由 |
| `scene.correction.inspect` | 评价 SHA-256 | 原有 `SceneDeltaEvaluation` / `DomainCorrectionPlan` 绑定 |
| `scene.disposition.verify` | disposition ID | 原有发布回执、源关卡和发布关卡字节复核 |

所有输入 schema 都声明 `additionalProperties: false`。服务端同时把 SDK 生成的 Pydantic 参数模型设为
`extra=forbid`，因此闭合 schema 不是文档装饰，而是真实执行行为。Tool annotations 全部为
read-only、idempotent、closed-world。

## 能力边界

这一步证明的是外部 Agent 能发现并安全调用 ArtFlow 已有能力，不是“接了 MCP 就变成 Agent”。真正
的 Agent 工程仍在 ArtFlow 自己的合同、策略、事件、Reducer、恢复、独立评价和 disposition 权限中。
当前 MCP 面只读，尚未开放新的场景变更提交；后续如果增加写工具，也必须先进入既有 reserve /
submit / reconcile 和 Unreal staging 路径，不能从协议适配器直接写宿主。

图生 3D 与新版 Scene Lab 不属于本切片，仍是 M10 后续工作。
